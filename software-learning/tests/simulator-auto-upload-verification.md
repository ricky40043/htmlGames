# 上傳自動重試驗證

架構設計模式的上傳新增最多三次自動重試，等待間隔為 2、4、8 秒。每次都是重新計算當下可用路徑，再傳送未確認封包；原封包失敗、歷次嘗試、實際接手機器仍留在封包狀態與上傳紀錄中。未開啟斷點續傳時，影片從 P1 重傳。

倒數可停止，也能按重傳立即開始；手動重傳會清除舊倒數，避免同時送出兩次。沒有可用共用儲存節點時不畫出不存在的成功路徑，達三次上限後才交回手動處理。等待重試仍列於進行中的操作清單，不會因歷史紀錄上限而消失。

頁面重新載入會中止舊頁面的倒數；保留的失敗請求可手動恢復，之後的新失敗會進入新的自動重試週期。其他模式的模擬契約未修改。

## 實測結果

- 既有 43 項 Node 測試及新增的等待重試紀錄保留測試：44/44 通過。
- simulator-auto-upload-browser.js：1440px、760px 各 26/26（分四階段 12 + 6 + 4 + 4）。
- 台灣 API 在 P3 傳送途中斷線：P1、P2 只傳一次，P3 留下失敗與成功兩次嘗試，2 秒後自動走美國 API，完成同一影片，無重複影片資料。
- 關閉斷點續傳：P3 斷線、機器恢复後，自動從 P1 重傳並完成。
- 共用儲存一直離線：三次重試後停止，後續封包未越過失敗封包傳送。
- 停止自動重試後不再偷跑；手動重傳仍能完成。
- 桌面倒數與 760px 重試耗盡畫面已檢視；無水平溢出、無瀏覽器 JavaScript 錯誤。
